# queue dev patchset apply hardening

`queue dev patchset apply` is the guarded apply path for patchsets generated by
`queue dev patchset create`.

The apply contract is deliberately conservative:

- `--help` and `-h` print usage without running preconditions.
- `--check` runs preconditions only and does not modify target files.
- Patchsets are extracted to an isolated temporary directory when applied from a zip.
- A pre-apply backup is created before any target file is overwritten.
- The backup includes `.queuebash/dev/patchset-backups/.../backup_manifest.json`.
- New files are listed in the backup manifest as rollback-delete candidates.
- JSON output includes the backup directory and backup manifest path.

## Scratchpad merge rule

`.queuebash/dev/scratchpad.json` is not a normal file-level replacement target.
Patchset apply must merge it at scratchpad item level.

When the target scratchpad already exists, the patchset apply path:

1. loads both scratchpad JSON files;
2. indexes existing `items[]` by `id`, `item_id`, or `key`;
3. appends incoming items with new IDs;
4. keeps identical existing items;
5. records differing duplicate IDs under `merge_conflicts` and keeps the target item;
6. appends a `queuebash.dev_patchset.scratchpad_merge.v1` entry to `merge_history`.

For this file only, full-file MD5 drift is reported as:

```text
ready_scratchpad_item_merge
```

rather than as a normal overwrite conflict.

## Commands

```bash
queue dev patchset apply --patchset PATCHSET.zip --target /path/to/tree --check
queue dev patchset apply --patchset PATCHSET.zip --target /path/to/tree --backup-dir /tmp/backs --json
```

Generated `apply_patchset.sh` files also support:

```bash
./apply_patchset.sh --help
./apply_patchset.sh --check TARGET
./apply_patchset.sh --backup-dir DIR TARGET
./apply_patchset.sh --json TARGET
```
