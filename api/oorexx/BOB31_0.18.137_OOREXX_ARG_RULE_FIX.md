# Bob31 0.18.137 ooRexx optional argument repair

This patch fixes the first live host failure in the ooRexx API wrapper.

## Root cause

Open Object Rexx omitted/unassigned variables do **not** become `.nil`.
They retain their symbolic uppercase name. The previous wrapper tested optional
constructor arguments with `.nil`, leaving fields as literal `ROOT`, `BINARY`,
and `SOURCEFILE`.

Observed host trace:

```text
Connected: BashQueues(root=ROOT BQSurface(not loaded))
source 'SOURCEFILE'
BINARY stats --json
RC(127)
```

## Fix

The wrapper now uses `arg()` before reading optional arguments and normalises
symbolic placeholders before applying defaults.

Affected areas:

- `ScriptFronted~init`
- `BashQueues~init`
- `.BashQueues~user`
- `.BashQueues~system`
- `_run`, `_runText`, `_parseJSON`, `_shquote`, `_log`
- `submit`, `explain`, `cancel`, `raw`
- namespace `exec`
- data/collection wrapper constructors

`lastError` and `last_error` are both exposed as public methods so example
failures report cleanly rather than raising `Object method not found`.

## No vendored JSON

The API still uses:

```rexx
::requires "json.cls"
```

This expects the platform/site ooRexx JSON class and does not vendor a copy.

## Host smoke test

From the repository root:

```bash
cd api/oorexx
QUEUEBASH_SOURCE=../../queuebash.sh rexx examples/bq_json_frontage_demo.rex
```

The connection line should show a real root, normally:

```text
Connected: BashQueues(root=/home/<user>/.queuebash BQSurface(not loaded))
```

The generated shell command must contain real values rather than `ROOT`,
`SOURCEFILE`, or `BINARY`.
