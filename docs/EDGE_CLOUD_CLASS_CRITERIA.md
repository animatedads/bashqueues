# Edge cloud class criteria

Edge classes should be used for workloads where edge locality, low latency, ingress control, and bounded artifact/log retention matter. These examples are contract templates only.

## Suggested criteria

- provider family and provider name
- account/project/service identity posture
- deployment/runtime type
- allowed region or edge placement policy
- data residency and cache/log retention requirements
- egress and ingress posture
- artifact/log destination and signed URL redaction
- legal/compliance framework mapping

Do not claim first-tier parity or compliance until primary-source validation and tests support it.
